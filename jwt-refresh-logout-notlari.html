1. Refresh Token İş Akışı (Token Rotation)

Amaç: Access token'ın süresi (15 dk) bittiğinde kullanıcıya tekrar şifre sordurmadan, elindeki uzun ömürlü refresh token ile yeni bir access token sağlamak.

İstemci (Tarayıcı / Mobil) │ POST /api/auth/refresh (Cookie veya JSON Body ile) ▼ [1] Controller: Token Nereden Geldi? (Cookie mi, Body mi?) │ ▼ [2] Servis: Veritabanında Bu Refresh Token Var mı? ├── Token daha önce iptal edilmiş mi? ➔ (Evet ise: ALARM! Replay Attack, tüm oturumları kapat!) ├── Token'ın süresi dolmuş mu? ➔ (Evet ise: DB'den sil ve reddet) └── Kullanıcı hesabı kilitli mi? │ ▼ [3] Servis: Token Rotation (Yenileme) ├── Kullanıcıya YENİ bir Access Token üretilir. └── Güvenlik gereği YENİ bir Refresh Token üretilir (Eskisi geride bırakılır). │ ▼ [4] Controller: İstemciye İletim ├── Yeni Refresh Token ➔ Set-Cookie başlığıyla (HttpOnly) tarayıcıya yazılır. └── Yeni Access Token ➔ Response Body içinde JSON olarak teslim edilir.

A) Controller Kodu ve Satır Satır Açıklaması

AuthController.java -> refresh() Spring MVC 
@PostMapping("/refresh")
public ResponseEntity<AuthResponse> refresh(
        // 1. Tarayıcıdan geliyorsa HttpOnly çerezdeki 'refreshToken' değerini yakala
        @CookieValue(name = "refreshToken", required = false) String cookieRefreshToken,
        // 2. Postman veya mobilden geliyorsa JSON Body'deki token'ı yakala
        @RequestBody(required = false) RefreshTokenRequest refreshTokenRequest) {

    // Öncelik çerezindir. Çerezde varsa onu al, yoksa Request Body'dekini al
    String token = (cookieRefreshToken != null && !cookieRefreshToken.isBlank())
            ? cookieRefreshToken
            : (refreshTokenRequest != null ? refreshTokenRequest.token() : null);

    // İki taraftan da hiçbir token gelmemişse hata fırlat
    if (token == null || token.isBlank()) {
        throw new TokenNotFoundException("Refresh token is missing");
    }

    // Servis katmanına git: Token'ı doğrula, eskiyi yak, yenilerini üret
    AuthResponse authResponse = authenticationService.refreshToken(new RefreshTokenRequest(token));

    // Üretilen yeni Refresh Token'ı tarayıcı için güvenli HttpOnly Cookie'ye paketle
    ResponseCookie cookie = createRefreshTokenCookie(authResponse.refreshToken(), securityProperties.getRefreshTokenExpiration());

    // Set-Cookie başlığı ile yeni çerezi tarayıcıya yazdır, gövdede token'ları dön
    return ResponseEntity.ok()
            .header(HttpHeaders.SET_COOKIE, cookie.toString())
            .body(authResponse);
}

B) Servis Kodu ve Satır Satır Açıklaması

AuthenticationService.java -> refreshToken() Service Layer 
@Transactional
public AuthResponse refreshToken(RefreshTokenRequest request) {

    // 1. Ham token'ı SHA-256 ile hashle, DB'de ara ve doğrula
    RefreshToken refreshToken = refreshTokenService.findByToken(request.token())
            .map(refreshTokenService::verifyRefreshToken)
            .orElseThrow(() -> new TokenNotFoundException("Refresh token not found"));

    User user = refreshToken.getUser();

    // 2. Kullanıcı hesabı banlanmış mı veya kilitli mi kontrol et
    if (!user.isEnabled() || !user.isAccountNonLocked()) {
        throw new TokenNotValidException("User account is locked or disabled");
    }

    // 3. Kullanıcıya YENİ bir Access Token üret
    String accessToken = jwtService.generateToken(new CustomUserDetails(user));

    // 4. TOKEN ROTATION: Kullanıcıya YENİ bir Refresh Token üret (Eski token artık geçersiz)
    RefreshToken newRefreshToken = refreshTokenService.createRefreshToken(user);

    // 5. Yeni ikiliyi geri dön
    return new AuthResponse(accessToken, newRefreshToken.getToken());
}

💡 Güvenlik Notu: verifyRefreshToken Metodu (Hırsızlık Alarmı)

Eğer bir saldırgan eski (önceden kullanılmış) bir refresh token ile istek atarsa (isRevoked() == true), sistem bunu anlar ve refreshTokenRepository.revokeAllByUser() çağırarak o kullanıcının açık olan tüm cihazlardaki oturumlarını güvenlik sebebiyle kapatır.

2. Logout (Çıkış) İş Akışı & Token Blacklist

Amaç: Kullanıcı çıkış yaptığında hem veritabanındaki Refresh Token'ı geçersiz kılmak, hem de stateless olan Access Token'ın süresi bitene kadar kullanılmasını engellemek için kara listeye (Blacklist) almaktır.

İstemci (Tarayıcı / Mobil) │ POST /api/auth/logout │ Headers : Authorization: Bearer <accessToken> │ Cookies : refreshToken=<refreshToken> ▼ [1] Controller: Token'ları Ayrıştır ├── "Authorization" header'ındaki "Bearer " kısmını at, accessToken'ı al. └── Cookie veya Body'den refreshToken'ı al. │ ▼ [2] Servis: Çift Yönlü İptal İşlemi ├── Refresh Token ➔ DB'de 'revoked = true' yapılır (Bir daha refresh yapılamaz). └── Access Token ➔ Çözümlenir, bitiş tarihi alınır ve TokenBlackList (RAM)'e eklenir. │ ▼ [3] Servis: Güvenlik Bağlamını Temizle └── SecurityContextHolder.clearContext() çağrılır. │ ▼ [4] Controller: Tarayıcıdaki Çerezi İmha Et └── cleanRefreshTokenCookie() ➔ maxAge(0) ile tarayıcıdaki çerez kalıcı olarak silinir.

A) Controller Kodu ve Satır Satır Açıklaması

AuthController.java -> logout() Spring MVC 
@PostMapping("/logout")
public ResponseEntity<Map<String, String>> logout(
        @RequestHeader(name = "Authorization", required = false) String authHeader,
        @CookieValue(name = "refreshToken", required = false) String cookieRefreshToken,
        @RequestBody(required = false) RefreshTokenRequest refreshTokenRequest) {

    // 1. Header doluysa ve "Bearer " ile başlıyorsa başındaki 7 harfi at, saf token'ı al
    String accessToken = null;
    if (authHeader != null && authHeader.startsWith("Bearer ")) {
        accessToken = authHeader.substring(7);
    }

    // 2. Refresh token'ı çerezden veya istek gövdesinden yakala
    String refreshToken = (cookieRefreshToken != null && !cookieRefreshToken.isBlank())
            ? cookieRefreshToken
            : (refreshTokenRequest != null ? refreshTokenRequest.token() : null);

    // 3. Servise git: Refresh token'ı DB'de öldür, Access token'ı kara listeye al
    authenticationService.logout(accessToken, refreshToken != null ? new RefreshTokenRequest(refreshToken) : null);

    // 4. Tarayıcıya 'bu çerezin süresi 0 saniyedir' emrini verecek boş bir çerez hazırla
    ResponseCookie cleanCookie = cleanRefreshTokenCookie();

    // 5. İstemciye Set-Cookie ile silme emrini gönder ve 200 OK mesajı dön
    return ResponseEntity.ok()
            .header(HttpHeaders.SET_COOKIE, cleanCookie.toString())
            .body(Map.of("message", "Successfully logged out!"));
}

B) Servis Kodu ve Satır Satır Açıklaması

AuthenticationService.java -> logout() Service Layer 
public void logout(String accessToken, RefreshTokenRequest refreshTokenRequest) {

    // 1. Refresh Token varsa: DB'de bul ve 'revoked = true' yap
    if (refreshTokenRequest != null && refreshTokenRequest.token() != null && !refreshTokenRequest.token().isBlank()) {
        refreshTokenService.logout(refreshTokenRequest.token());
    }

    // 2. Access Token varsa: Süresi dolana kadar birisi kullanmasın diye kara listeye al
    if (accessToken != null && !accessToken.isBlank()) {
        try {
            // Token'ın geçerlilik bitiş tarihini (expiration) oku
            Claims claims = jwtService.extractAllClaims(accessToken);
            Instant expiration = claims.getExpiration().toInstant();

            // TokenBlackListService'deki ConcurrentHashMap'e ekle
            tokenBlackListService.blacklistToken(accessToken, expiration);
        } catch (JwtException | IllegalArgumentException e) {
            // Token zaten geçersizse sessizce devam et
        }
    }

    // 3. Spring Security oturumunu (Thread context) temizle
    SecurityContextHolder.clearContext();
}

3. Çerez (Cookie) Güvenliği & Yardımcı Metotlar

AuthController.java -> Cookie Metotları 
// Token oluştururken:
private ResponseCookie createRefreshTokenCookie(String token, Duration maxAge) {
    return ResponseCookie.from("refreshToken", token)
            .httpOnly(true)      // XSS Koruması: JS (document.cookie) okuyamaz!
            .secure(false)       // Localhost için false (Canlıda HTTPS ile true olmalı)
            .sameSite("Strict")  // CSRF Koruması: Sadece bizim siteden gelen isteklerde gönderilir
            .path("/api/auth")   // Yalnızca auth uç noktalarına giden isteklerde taşınır
            .maxAge(maxAge)      // 7 gün boyunca geçerli
            .build();
}

// Token silerken (Logout anında):
private ResponseCookie cleanRefreshTokenCookie() {
    return ResponseCookie.from("refreshToken", "") // Değeri boş string
            .httpOnly(true)
            .secure(false)
            .sameSite("Strict")
            .path("/api/auth")
            .maxAge(0)           // Ömür 0 saniye -> Tarayıcı anında hafızadan siler
            .build();
}

⚠️ Küçük Kod Düzeltmesi Hatırlatması

AuthController.java 58. satırında: if (token != null || token.isBlank()) yazılmıştır. Burada != null yerine == null (yani if (token == null || token.isBlank())) olmalıdır. Aksi halde token dolu gelse bile hata fırlatacaktır.
